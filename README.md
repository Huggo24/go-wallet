# Wallet API

## Стек технологий

- **Go** — язык разработки.
- **PostgreSQL** — реляционная база данных.
- **pgx** — драйвер PostgreSQL и пул соединений.
- **Docker** — контейнеризация приложения.
- **Docker Compose** — управление окружением приложения.

## Архитектура

Проект использует разделение ответственности между HTTP-обработчиками и слоем доступа к данным.

Основные компоненты:

- **Handler** — обработка HTTP-запросов, проверка входных данных и формирование HTTP-ответов.
- **Repository** — выполнение запросов к PostgreSQL.
- **Models** — структуры данных и доменные ошибки.

## База данных

Для хранения данных используется PostgreSQL.

Таблицы:

- `wallets` — хранение идентификаторов кошельков и их балансов.

Изменение баланса выполняется атомарными SQL-запросами.

## API

- **GET /api/v1/wallets/{WALLET_UUID}**

- **POST /api/v1/wallet**
Формат входных данных:
{
    walletid: UUID,
    operationType: DEPOSIT | WITHDRAW,
    amount: INTEGER
}


## Запуск приложения

### Конфигурация

В корневой директории проекта необходимо настроить файл `config.env`:

```env
POSTGRES_DB=postgres_db
POSTGRES_USER=postgres_user
POSTGRES_PASSWORD=your_password
POSTGRES_HOST=postgres
POSTGRES_PORT=5432
```

POSTGRES_PORT используется только внешним соединением. Внутри контейнера обмен происходит по порту 5432.

### Запуск

Сборка и запуск приложения:

```bash
docker compose up --build
```

После запуска API будет доступно по адресу:

```text
http://localhost:8080
```

## Тестирование

Для запуска тестовой среды:

```bash
docker compose -f docker-compose-test.yml up --build
```

Тесты запускаются локально посредством *go*:

```bash
go test ./...
```

В проекте предусмотрены тесты:
- Тестирование HTTP-обработчиков.
- Тестирование операций с базой данных.
- Проверка конкурентного изменения баланса.
- Нагрузочное тестирование HTTP API.

Фактическое обращение к тестовому серверу происходит только в нагрузочном тестировании. Остальные тесты используют httptest.


## Нагрузочное тестирование

Для оценки производительности реализован собственный инструмент нагрузочного тестирования, позволяющий отправлять параллельные HTTP-запросы к API.

В среднем на один кошелек сервер обрабатывает ~1000 запросов в секунду.

Конфигурация теста:
- 50 воркеров
- MinConns соединения с базой: 10
- MaxConns соединения с базой: 50
